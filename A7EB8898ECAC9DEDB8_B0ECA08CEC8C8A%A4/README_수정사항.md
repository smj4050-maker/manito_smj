# 울장복 마니또 사이트 개선판 (2026-11-20)

## 수정된 부분
1. 방장 모드의 구성원 수정: 해당 직원 명단 아래에서 이름/부서를 바로 수정합니다. 저장할 때 원래의 변경 경고/Firestore 기록 과정을 사용합니다.
2. 선물 준비 완료: 2026년 11월 20일 00:00(한국시간)부터 버튼을 활성화합니다. 버튼 문구에 표시된 '23일'은 실제 선물 준비일로 유지합니다.
3. 활동 진행/일촌평 버튼: 손가락으로 누르기 쉽게 크기와 아이콘 확대.
4. 캐릭터 모션: 기존 30개 이미지 기반 걷기, 손 흔들기, 하트, 독서, 앉기 동작에 더 촘촘한 키프레임과 서로 다른 움직임 속도 적용.
5. 70명 수준의 미니룸: 화면 비활성일 때 이동 계산을 멈추고, 인원이 많을수록 갱신 주기를 줄입니다. 깊이 정렬 순서가 바뀔 때만 DOM 재배치.

## 적용 방법
- 리포지토리 루트에 이 ZIP의 내용을 그대로 올려주세요. 기존 `source/` 폴더를 덮어쓰고 `.github/workflows/pages.yml`을 추가합니다.
- GitHub `Settings > Pages > Build and deployment > Source`가 `GitHub Actions`인지 확인합니다.
- `Actions`에서 `Deploy Manito to GitHub Pages`가 성공하면 기존 Pages 주소에서 새 사이트가 표시됩니다.
- 직접 로컬 빌드: Node.js 24 설치 후 `cd source && npm ci && npm run build`하면 루트에 `index.html`이 만들어집니다.

## 주의사항
- 이 ZIP에는 기존의 미빌드 index.html을 의도적으로 넣지 않았습니다. GitHub Actions가 개선된 코드로 index.html을 생성합니다.
- Firebase 운영 데이터와 Firestore 규칙은 수정하지 않았습니다.
- 실제 기기 70대 동시 로그인/쓰기 부하 테스트는 미수행입니다. 이동 계산만 70명 × 1000회 시뮬레이션하여 오류 없음 확인.
- 현재 방문자 카운터는 하나의 Firestore 카운터 문서로 트랜잭션 업데이트하므로 실제 70명 동시 접속 상황에서 경합 가능성이 있습니다. 카운터 자체를 안전하게 분산하려면 Firestore 데이터와 규칙 마이그레이션을 별도로 진행해야 합니다.
- 이름 변경은 이전 코드와 같이 기존 배정을 초기화할 수 있습니다. 부서만 변경할 때는 이름을 그대로 유지해주세요.
- 원본에 있던 캐릭터 이미지를 새로운 자세별 이미지로 그린 것은 아닙니다. CSS 동작 프레임을 개선한 것입니다.
